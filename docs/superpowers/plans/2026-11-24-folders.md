# 폴더 기능 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 글을 Obsidian식 폴더 트리로 묶고, 사이드바를 목록 보기/폴더 보기 중에서 골라 쓸 수 있게 한다.

**Architecture:** `.hype`에 `tree: TreeNode[]`를 추가하고, 이 트리를 글 순서의 유일한 기준으로 삼는다. 트리 조작은 순수 함수 모듈 `src/stores/tree.ts`에 두고, 프로젝트 스토어가 그 함수를 호출한 뒤 `chapters` 배열을 펼친 순서대로 다시 정렬한다. 그래서 내보내기 코드는 바꾸지 않는다. 사이드바는 목록 보기와 재귀 트리 보기 컴포넌트로 나누고, 드래그는 HTML5 DnD로 구현한다.

**Tech Stack:** Vue 3 + Pinia + TypeScript, Tauri v2, vitest(새로 추가)

**Spec:** `docs/superpowers/specs/2026-11-24-folders-design.md`

## Global Constraints

- 프로젝트 파일 `version`: `'1.1'`(새로 저장할 때). `tree`가 없는 1.0 파일도 열려야 한다.
- 불변식: `chapters`의 모든 id가 `tree`에 정확히 한 번씩 나온다.
- 트리가 바뀔 때마다 `chapters` 배열을 깊이 우선으로 펼친 순서와 같게 맞춘다.
- 폴더 접기/펴기는 `isDirty`를 켜지 않는다. 다른 트리 변경은 모두 `isDirty = true`.
- 보기 설정은 `settings` 스토어(localStorage `hypewriter-settings`)의 `sidebarView: 'list' | 'tree'`에 둔다. 기본값은 `'tree'`.
- UI 문구는 한국어로 쓴다: "새 폴더", "새 챕터", "목록 보기", "폴더 보기", "삭제".
- **커밋하지 않는다.** 사용자가 나중에 직접 하겠다고 했다. 각 Task의 끝은 검증까지다.
- 타입 검사는 `vue-tsc` 1.8이 바로 죽는 문제가 있으니 쓰지 않는다. `npm run build`(vite)와 `npx tsc --noEmit -p .`의 `.ts` 결과로 확인한다.

## Review Focus

- 1.0 파일(`tree` 없음)을 열면 모든 글이 기존 순서 그대로 루트에 놓여야 한다. → Task 2 `opens 1.0 file`
- `tree`가 이미 지운 글을 가리키거나 글 하나를 빠뜨린 손상된 파일은 조용히 보정돼야 한다. → Task 1 `normalizeTree` 테스트
- 폴더를 자기 자신이나 자기 하위 폴더로 옮기면 아무 일도 일어나지 않아야 하고, 노드가 사라지면 안 된다. → Task 1 `moveNode rejects cycle`
- 항목을 자기 자신의 앞이나 뒤에 놓아도 트리가 그대로여야 한다. → Task 1 `moveNode onto itself`
- 폴더 안에 있는 선택된 글을 지우면 펼친 순서상 바로 앞 글이 선택돼야 한다(앞 글이 없으면 다음 글). → Task 2 `delete selected chapter in folder`

  ```ts
  export interface ChapterNode { type: 'chapter'; id: string }
  export interface FolderNode { type: 'folder'; id: string; name: string; collapsed: boolean; children: TreeNode[] }
  export type TreeNode = ChapterNode | FolderNode
  export type DropTarget =
    | { kind: 'before' | 'after'; refId: string }
    | { kind: 'inside'; folderId: string }   // 폴더 끝에 넣기
    | { kind: 'root-end' }
  export function flattenChapterIds(tree: TreeNode[]): string[]
  export function findNode(tree: TreeNode[], id: string): TreeNode | null
  export function normalizeTree(tree: TreeNode[] | undefined, chapterIds: string[]): TreeNode[]
  export function insertNode(tree: TreeNode[], node: TreeNode, target: DropTarget): TreeNode[]
  export function removeNode(tree: TreeNode[], id: string): TreeNode[]
  export function canMove(tree: TreeNode[], nodeId: string, target: DropTarget): boolean
  export function moveNode(tree: TreeNode[], nodeId: string, target: DropTarget): TreeNode[]
  export function dissolveFolder(tree: TreeNode[], folderId: string): TreeNode[]
  export function updateFolder(tree: TreeNode[], folderId: string, patch: Partial<Pick<FolderNode, 'name' | 'collapsed'>>): TreeNode[]
  export function dropPosition(nodeType: 'chapter' | 'folder', offsetY: number, height: number): 'before' | 'after' | 'inside'
  ```

- [ ] **Step 2: 실패하는 테스트 작성** (`src/stores/tree.test.ts`)

테스트 픽스처: `c(id)` = 글 노드, `f(id, children)` = `{type:'folder', id, name:id, collapsed:false, children}`.
기본 트리 `T = [c('a'), f('F', [c('b'), f('G', [c('c')])]), c('d')]`

```ts
test('flattenChapterIds: 깊이 우선', () => expect(flattenChapterIds(T)).toEqual(['a','b','c','d']))

test('normalizeTree: undefined면 모든 글을 루트에 순서대로', () =>
  expect(normalizeTree(undefined, ['x','y'])).toEqual([c('x'), c('y')]))
test('normalizeTree: 없는 id 제거, 빠진 글은 루트 끝에', () =>
  expect(flattenChapterIds(normalizeTree(T, ['a','c','d','z']))).toEqual(['a','c','d','z']))
test('normalizeTree: 중복된 글 노드는 첫 번째만 남김', () =>
  expect(flattenChapterIds(normalizeTree([c('a'), f('F',[c('a')])], ['a']))).toEqual(['a']))
test('normalizeTree: 빈 폴더는 유지', () =>
  expect(normalizeTree([f('E', [])], [])).toEqual([f('E', [])]))

test('insertNode before/after/inside/root-end', () => {
  expect(flattenChapterIds(insertNode(T, c('n'), {kind:'before', refId:'c'}))).toEqual(['a','b','n','c','d'])
  expect(flattenChapterIds(insertNode(T, c('n'), {kind:'after', refId:'G'}))).toEqual(['a','b','c','n','d'])
  expect(flattenChapterIds(insertNode(T, c('n'), {kind:'inside', folderId:'F'}))).toEqual(['a','b','c','n','d'])
  expect(flattenChapterIds(insertNode(T, c('n'), {kind:'root-end'}))).toEqual(['a','b','c','d','n'])
})

test('moveNode: 글을 다른 폴더로', () =>
  expect(flattenChapterIds(moveNode(T, 'a', {kind:'inside', folderId:'G'}))).toEqual(['b','c','a','d']))
test('moveNode: 폴더째 이동', () =>
  expect(flattenChapterIds(moveNode(T, 'G', {kind:'after', refId:'d'}))).toEqual(['a','b','d','c']))
test('moveNode rejects cycle', () => {
  expect(canMove(T, 'F', {kind:'inside', folderId:'G'})).toBe(false)
  expect(canMove(T, 'F', {kind:'inside', folderId:'F'})).toBe(false)
  expect(canMove(T, 'F', {kind:'before', refId:'c'})).toBe(false)
  expect(moveNode(T, 'F', {kind:'inside', folderId:'G'})).toEqual(T)
})
test('moveNode onto itself', () => {
  expect(moveNode(T, 'b', {kind:'before', refId:'b'})).toEqual(T)
  expect(moveNode(T, 'b', {kind:'after', refId:'b'})).toEqual(T)
})
test('입력 트리를 변경하지 않음', () => {
  const snap = structuredClone(T); moveNode(T, 'a', {kind:'root-end'}); expect(T).toEqual(snap)
})

test('dissolveFolder: 자식을 폴더 자리에 꺼냄', () => {
  const r = dissolveFolder(T, 'F')
  expect(r.map(n => n.id)).toEqual(['a','b','G','d'])
  expect(flattenChapterIds(r)).toEqual(['a','b','c','d'])
})
test('dissolveFolder: 하위 폴더', () =>
  expect((dissolveFolder(T, 'G')[1] as FolderNode).children.map(n => n.id)).toEqual(['b','c']))

test('updateFolder', () =>
  expect((updateFolder(T, 'G', {collapsed:true}) [1] as FolderNode).children[1]).toMatchObject({collapsed:true}))

test('dropPosition', () => {
  expect(dropPosition('chapter', 4, 20)).toBe('before')
  expect(dropPosition('chapter', 15, 20)).toBe('after')
  expect(dropPosition('folder', 3, 20)).toBe('before')    // 위 25%
  expect(dropPosition('folder', 10, 20)).toBe('inside')
  expect(dropPosition('folder', 17, 20)).toBe('after')    // 아래 25%
})
```

4. 목록 보기에서 순서를 바꾼 뒤 폴더 보기로 전환하면 놓은 자리 옆 글과 같은 폴더에 들어가 있다.
5. 드래그한 뒤 `isDirty` 표시(저장 버튼 강조)가 켜진다.
6. 내보내기(PDF) 순서가 사이드바 순서와 같다.

Windows 확인은 CI 빌드 산출물로 따로 해야 한다는 점을 사용자에게 보고한다.
