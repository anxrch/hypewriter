# 폴더 기능 설계

2026-11-24 · 상태: 승인 대기

## 의도

글(챕터)이 늘어나면 사이드바의 평평한 목록만으로는 정리가 어렵다. Obsidian처럼 글을 폴더로 묶을 수 있게 하고, 사용자가 사이드바를 **목록 보기**(지금처럼 평평하게)와 **폴더 보기**(트리) 중 편한 쪽으로 골라 쓸 수 있게 한다. 두 보기는 같은 데이터를 보여 주는 화면일 뿐이다.

## 목표

- 폴더 만들기·이름 바꾸기·삭제, 폴더 안에 폴더 넣기(깊이 제한 없음), 접기/펴기
- 글과 폴더를 드래그해서 순서 바꾸기, 폴더에 넣기·빼기
- 폴더에 넣지 않은 글도 맨 위(루트)에 둘 수 있다. 폴더는 선택 사항이다.
- 사이드바 상단에서 목록 보기 ↔ 폴더 보기 전환
- 두 보기와 내보내기의 글 순서가 언제나 같다.
- 기존 `.hype` 파일이 그대로 열린다.

## 비목표

- 내보내기(DOCX/PDF)에 폴더를 "1부/2부" 같은 상위 제목으로 넣는 기능. 내보내기는 지금처럼 글만 순서대로 출력한다.
- 실제 디스크 폴더나 파일로 나누기. 프로젝트는 계속 `.hype` 파일 하나다.
- 여러 항목 한꺼번에 선택해서 옮기기, 폴더 색·아이콘

## 하지 말아야 할 것 (실패로 보는 경우)

- 목록 보기와 폴더 보기의 순서가 어긋나는 것
- 폴더를 지웠다가 안에 있던 글까지 사라지는 것
- 기존 파일을 열었는데 글이 빠지거나 순서가 바뀌는 것

## 고려한 방식

| 방식 | 장점 | 단점 | 결과 |
|---|---|---|---|
| **A. 트리 하나를 기준으로 저장** | 순서가 하나라 두 보기와 내보내기가 항상 일치. Obsidian식 트리와 자연스럽게 맞음 | 목록 보기에서 글을 옮기다 폴더 경계를 넘으면 소속 폴더가 바뀜(화면엔 폴더가 안 보임) | **선택** |
| B. `chapters` 배열 순서 + 글마다 `folderId` | 목록 보기가 단순 | 폴더 묶음과 배열 순서가 어긋나 폴더 보기·내보내기 순서가 달라 보임 | 제외 |
| C. 보기마다 순서를 따로 저장 | 각 보기가 독립적 | 내보내기 순서가 애매해짐 | 제외 |

## 데이터 모델

`Project`에 `tree`를 추가한다. 글 내용은 계속 `chapters`에 둔다.

```ts
type TreeNode =
  | { type: 'chapter'; id: string }            // chapters[].id 참조
  | { type: 'folder'; id: string; name: string; collapsed: boolean; children: TreeNode[] }

interface Project {
  version: '1.1'          // 1.0 → 1.1
  // ...기존 필드
  chapters: Chapter[]
  tree: TreeNode[]        // 루트 항목들
}
```

**불변식:** `chapters`의 모든 id가 `tree`에 정확히 한 번씩 나온다.

**정렬 순서:** 글 순서는 트리를 깊이 우선으로 펼친 순서다. 목록 보기, 내보내기, 첫 글 선택이 모두 이 순서를 따른다.

**`chapters` 배열 동기화 (내 판단):** 트리가 바뀔 때마다 `chapters` 배열도 펼친 순서로 다시 정렬한다. 그러면 내보내기 코드(`ExportModal.vue`, Rust 쪽)를 고치지 않아도 되고, 옛 버전 앱으로 열어도 순서가 맞다.

**불러오기 보정:** 파일을 열 때 `tree`가 없으면(1.0) 모든 글을 `chapters` 순서대로 루트에 둔다. `tree`가 있으면 `chapters`에 없는 id는 지우고, 트리에서 빠진 글은 루트 끝에 붙인다.

## 동작

### 공통
- 사이드바 상단 섹션 헤더에 보기 전환 토글(목록/폴더)을 둔다. **보기 설정은 프로젝트가 아니라 앱 설정(`settings` 스토어)에 저장한다** (내 판단). 사용자 취향이기 때문이다.
- 글 추가(헤더의 `+`): 루트 끝에 새 글을 만든다.
- 글 삭제: `chapters`와 `tree`에서 함께 지운다.

### 폴더 보기
- 헤더에 "새 폴더" 버튼. 루트 끝에 "새 폴더"를 만들고 바로 이름 편집 상태로 들어간다.
- 폴더 줄: 접기 화살표, 이름, 마우스를 올리면 `+`(이 폴더 안 끝에 새 글)와 삭제 버튼
- 폴더 이름은 더블클릭으로 편집한다(글 제목 편집과 같은 방식).
- 폴더 삭제: 폴더만 없애고, 안에 있던 항목은 폴더가 있던 자리에 순서대로 꺼낸다. 확인 창은 띄우지 않는다(글이 사라지지 않으므로).
- 접기/펴기 상태(`collapsed`)는 파일에 저장하지만, 바꿔도 "저장 안 됨(dirty)" 표시는 켜지 않는다 (내 판단).
- 드래그: 글이나 폴더를 다른 항목 **위/아래**에 놓으면 그 앞/뒤로, 폴더 **가운데**에 놓으면 그 폴더 안 끝으로 들어간다. 폴더를 자기 자신이나 자기 하위 폴더 안으로는 옮길 수 없다. 단, 접힌 폴더 안에 넣는 것은 된다.
- 들여쓰기로 깊이를 표시한다.

### 목록 보기
- 트리를 펼친 순서대로 글만 보여 준다. 폴더는 보이지 않는다.
- 드래그: 글 X를 글 Y의 위/아래에 놓으면 X는 **Y가 속한 폴더**의 Y 앞/뒤로 옮겨진다. 폴더 경계를 넘으면 소속 폴더가 바뀔 수 있는데, 이는 방식 A를 고르면서 받아들인 동작이다.

## 구조 (빌더 재량)

- 트리 조작은 순수 함수 모듈(예: `src/stores/tree.ts`)로 분리한다: flatten, 노드 찾기·삭제·삽입, 이동 가능 여부 검사, 불러오기 보정. 스토어는 이 함수를 부르고 `chapters` 동기화와 `isDirty`를 맡는다.
- 사이드바는 재귀 트리 노드 컴포넌트와 목록 보기로 나눈다. `Sidebar.vue`가 이미 크니 분리하는 편이 좋다.
- 드래그 구현: Tauri v2는 창에서 파일 드롭을 받는 기능(`dragDropEnabled`)이 기본으로 켜져 있어서 Windows에서 HTML5 드래그앤드롭을 가로챈다. 앱은 파일 드롭을 쓰지 않으니 `tauri.conf.json` 창 설정에서 `"dragDropEnabled": false`를 넣고 HTML5 DnD를 쓰는 방법과, 포인터 이벤트로 직접 구현하는 방법 중 빌더가 고른다. Linux(WebKitGTK)에서도 실제로 동작하는지 확인해야 한다.
- 테스트: 지금 프로젝트에는 테스트 도구가 없다. 트리 순수 함수에 한해 vitest를 붙이는 것을 권한다.

## 남은 결정 (빌더 재량)

- 드롭 위치 표시선과 강조 모양, 폴더 아이콘(lucide `Folder`/`FolderOpen`)
- 드래그 중 접힌 폴더 위에 잠시 머무르면 자동으로 펼칠지 여부
